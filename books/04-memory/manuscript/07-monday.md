Pick one agent you already use. Leave the memory features of new products for a later week. You will learn more from auditing the memory you have than from adding more.

Choose the one that touches the most important work, or the most customer information. If you are not sure, choose the one whose output people trust without checking. That trust is the thing to test.

Then do this once, with a timer. Ninety minutes is enough.

1. **List what it can see.** Everything given to it before the first word of a task: saved instructions, attached files, a notes page, a memory feature, an index. Write each item on its own line.
2. **Sort onto the five shelves.** Brief, trace, case file, standing notes, archive. Anything that fits none is probably a standing note in disguise, or a document nobody owns.
3. **Date and own each item.** Who wrote it, and when? Mark every unknown.
4. **Read the standing notes as a stranger.** Is each one scoped? Does any contradict another? Would you want each one to win against today's brief?
5. **Delete what you cannot defend.** Not archive. Delete, or move out of view. Old and unowned is enough reason.
6. **Add a precedence block** from the contradiction chapter at the top of what the agent sees. Four lines.
7. **Pick the largest customer-data gap.** Usually traces or exports. Give it a number of days, and the mechanism that enforces it.
8. **Write the one-page policy.** Fill the template. It will have blanks. Mark them and assign owners.
9. **Run one real job** and read the trace. Find which items steered it. Check that the handback names any overridden note.

If the first run surprises you, the audit found something. Write down the item and its shelf, and fix the shelf.

If you are the builder, add three things this week. Log which memory items entered each run, with their dates. Give retrieval a status filter so superseded documents stay out of the results. Give the index a removal path, so that deleting a source deletes its chunks. Those three alone turn most memory mysteries into things you can look up.

If you lead a team, bring the page to a meeting and ask for the owner's name. If nobody volunteers, you have found the real finding.

## A short script for a skeptical colleague

Someone will say the agent works fine. Ask three questions, and keep a straight face.

- "What does it know about us before we type anything?"
- "Who can change that, and who would notice?"
- "If a customer asked us to forget them today, how would we show that we had?"

If they can answer all three, they have already done this chapter. If not, offer to do the audit together. It takes an afternoon, and it ends with a list.

## What to ignore for now

Ignore the pressure to give the agent a lifelong memory of everything it has done. The goal is not an agent that knows you. The goal is an agent that knows the right twelve things about your work, in the right place, with the right dates. A smaller memory you trust is worth more than a larger one you do not.

Ignore the claim that a bigger window removes the need for any of this. A bigger window lets you put more in view. It does not tell the loop which sentence to obey. A thousand pages in view is still a pile, and the model still weighs it by vividness and position. The shelves are about authority, which size does not supply.

Ignore the urge to automate memory writes before you can read what is written. Review the proposals by hand for a month. When ninety-five of a hundred are fine and the five bad ones are cheap to fix, relax the review for those categories. Not before.

Ignore the feeling that deleting is risky. Keeping an item you cannot defend is the larger risk, and it grows every week. A deleted note can be rewritten in a minute, once you know you need it.

## One page, one owner, one clock

The book comes down to three things you can do before the week is out.

A page that says what each shelf holds and who may write to it. A name on that page, with a backup. A clock on every shelf that holds customer data, enforced by something that runs without anyone remembering.

Everything else in this book supports those three: the shelves, so you know what to put where; retrieval, so the archive earns its place; precedence, so conflicts are settled by you; handoffs, so a fresh thread does not lose the work.

The next book moves from memory to work. Book 5 takes the same loop into research, writing, operations, support, and software changes, one pattern per job, each with a failure mode named in advance. Bring the page you wrote this week. Each of those jobs will ask what the agent is allowed to remember.
