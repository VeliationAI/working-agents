title: Three kinds of work
---

Sort the work before you pick a design. The loop is a good fit for some jobs and an expensive fit for others. A workflow is not a consolation prize. For a known path, it is the better machine.

## Transform

You already have the material. Summarize, reformat, translate, pull fields into a table, rewrite in the house style.

The path is known before you see the quirks of the case. Build a workflow. An agent adds steps, cost, and ways to wander, and it will sometimes "improve" a text you wanted held steady. Give the workflow the style rules and a check for the fields you require. Let it run the same way every time.

## Find and compose

The shape of the answer is known. The material is not in your hands yet. The path depends on what turns up.

Research briefs. Meeting prep. A comparison of three vendors from their own documentation. A note on why a metric moved, using the warehouse and the incident log.

This is the sweet spot for a read-only agent. Tight goal. Named sources. A source rule. A stop that allows the answer to be incomplete. The Thursday renewal brief in the goals chapter is this kind of work. You know the four sections. You do not know, before you look, which invoices exist.

Stay read-only here until the handback is something you can check quickly. The value is the composed picture with sources. The value is not the system taking the next action on its own.

## Change the world

Send, file, pay, merge, delete, schedule, reply to a customer, edit a live record.

The path may be unclear, and the cost of a wrong action is paid by someone else. Use an agent here only with drafts, approvals, narrow write tools, and a log you can replay. Start by letting it prepare the change. A person performs the change. Graduate one action at a time, after the drafts have been dull and correct for a while.

A coding example, for people who ship software: the loop may prepare a change and open it as a proposal. A person merges it. The day you let the loop merge is a different system, with a different check. Treat that day as a decision, and record it.

A support example: the loop may draft a reply that quotes the policy. It may not send, and it may not promise a credit the policy does not allow. The draft is the product. Sending is a later permission, if it ever becomes one.

## Judgment stays with a person

Some work should not be given a finish line the loop is allowed to cross.

Should we fire this vendor? Is this message kind enough to send to a frightened customer? Is this exception fair?

An agent can gather the facts, list options, and quote the policy. The decision stays with a person, because the finish line is a value, and a value is a poor thing to delegate to a check you wrote in a hurry. Ask for the brief. Keep the decision.

When you watch a demo, sort it out loud. A transform wearing the costume of an agent is still a workflow, and it may be a very good workflow. Name it honestly. You will buy it for the right reasons, and you will refuse to give it write tools it does not need.
