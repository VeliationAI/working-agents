## Terms

**Agent.** A model in a loop with a goal, a way to observe, a way to act, and a check, inside limits you set.

**Assistant.** A product name. It may be a chatbot, a workflow, or an agent. The name is not the design.

**Brief.** The one-page description of the job, the output, the tests, the boundaries, and the stop.

**Chatbot.** A system that answers a turn and stops.

**Check.** The beat that compares the current result with the goal, and decides to continue, repair, or hand the work back.

**Handback.** What the loop returns when it stops. Result, checks, unknowns, and sources.

**Harness.** The software that runs the loop around the model. Also called a runtime or a framework. The harness sends tool calls, stores the trace, and enforces limits.

**Prompt.** The instruction for a turn.

**Retrieval.** Finding a passage in a collection and giving it to the model. Retrieval can sit inside a workflow or inside an agent. It is not, by itself, an agent.

**Tool.** A function the loop is allowed to call, such as search, read a record, or save a draft.

**Trace.** The record of a run. Each goal, observation, action, and check, in order.

**Workflow.** A fixed path of steps. A model may write inside a step. It does not choose the path.

## What this book is claiming

It claims that the useful question is whether a goal, an observation, an action, and a check are actually present.

It claims that a workflow is the right design when you can write the steps before you see the case.

It claims that write actions deserve drafts, approvals, and traces.

It claims that fluency is a weak test of truth.

It does not evaluate vendors. It does not report scores. Product names and features change faster than a field guide should. A sentence that would be true for one product in one month does not belong here. The loop outlasts the homepage.
