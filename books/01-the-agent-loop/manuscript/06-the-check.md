The loop is only as honest as its check.

A fluent paragraph can pass a tired reader and fail every test you meant to set. The check exists so that trust is cheaper than starting over, and so that trust is still earned.

## Three checkers

Use at least two.

The model checks itself. This is cheap, and it is biased toward saying the work is done. It is useful for obvious gaps. A missing section. The wrong format. A claim with no source sitting in the trace. It is a weak final authority for anything a person will rely on.

A program checks. Counts, required fields, tests, forbidden phrases, "every number appears in a retrieved source", "the file exists and the old name does not". Use a program whenever the test can be stated exactly. Programs stay pedantic on a Friday afternoon. That is the point.

A person checks. You want a person when the action is hard to undo, when a mistake spends someone else's time or trust, or when the goal includes taste and judgment. Approval is a step the loop waits on. It has a place in the trace, the same as any other tool.

Match the checker to the cost of being wrong. A summary of a public webpage can live with a lighter check than a reply that promises a refund. The lighter check should still look at sources. The heavier check should still be fast enough that people actually do it.

## A handback a person can use

Design the output so the human check takes minutes, not a second research project. A useful handback has five parts, in this order.

1. The result, first. The briefing, the draft, the new file name.
2. The checks that passed. Four sections present. No outbound message sent. Dates in the agreed form.
3. The unknowns and the open questions. Billing had no invoice for this account. Treated as unknown, not as zero.
4. The sources, with enough detail to reopen them. Document name, record id, date, section.
5. What the loop refrained from doing. Especially any write action it did not take.

If you have to redo the research to believe the brief, the loop saved you no work. It assigned you reading. Fix the handback before you add another tool.

## The self-critique trap

"Review your work and fix any issues" often produces a confident rewrite that adds new claims. The model is good at sounding corrected.

Prefer a checklist tied to the original tests.

- Are all four sections present?
- Does every number appear in a source retrieved for this run?
- Are missing facts marked unknown?
- Was any message sent?

Yes or no, with a pointer to the line. A critique that cannot point at a test is another paragraph. You already had paragraphs.

Keep the tests visible to the checker. A hidden rubric guarantees an argument later about whether the run succeeded. The tests in the brief are the rubric. The handback quotes them.
