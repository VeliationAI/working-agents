A common goal for "agent memory" is to remember everything. That goal fights the loop. A long, messy history makes the next action worse. The model attends to a vivid detail, an old instruction, a joke in the middle of the log, and loses the finish line.

Memory is a set of choices about what stays in view.

## Five shelves

Keep the shelves separate. When they collapse into one transcript, you will not know which sentence is allowed to steer the next run.

The brief. The goal, the tests, the boundaries, and the stop rule. This stays in view on every beat. If the brief is long, keep a short version in view and the full version one lookup away.

The trace. What the loop just did and what came back. The trace stops the loop from repeating a failed search and lets you replay a mistake. Trim it. Keep results. Drop banners, boilerplate, and duplicated instructions.

The case file. Facts about this task that should survive the session. What the customer bought. Decisions already made. Sources used. Write the case file on purpose. A chat log is a weak substitute, because it mixes the job with every dead end.

The standing notes. Preferences that apply across tasks. Briefs use short sentences. Dates are written year-month-day. A customer draft never names a competitor. Keep this shelf small, reviewed, and easy to delete. A standing note is an instruction you are willing to defend on every future job.

The archive. Old tasks, searchable when the goal says the past matters. The archive is a tool the loop calls. It is not a packet stuffed into every run.

Retrieval belongs here as a word you will meet. Retrieval finds a passage in a collection and gives that passage to the model. People also call a common version of this RAG, for retrieval-augmented generation. Retrieval can be one step in a workflow, or one tool inside a loop. A system that retrieves a paragraph and answers once is not, by that fact alone, an agent. An agent may use retrieval and still be an agent because of the loop, not because of the search.

## Forgetting is part of the design

When the job is done, the trace can go. When a standing note is wrong, edit it or delete it. A note you only "update" by adding a newer sentence will lose to the older one at the worst moment, because both are still in view and the older one may be more specific.

An agent that remembers a rejected approach will propose it again, often with confidence, because the memory does not say "rejected" loudly enough. Write the decision, not only the idea. "We do not offer a goodwill refund on this plan. Confirmed by the policy owner on 2026-04-02."

Customer data needs an owner and a clock. If a case file holds tickets, invoices, or personal details, decide how long it lives and who can delete it. A memory you cannot delete is a liability with a friendly name.

## If you are not the builder

You still choose what goes on the shelves. Pasting a forty-page policy into the chat buries the finish line. Point at the part that matters.

Using section 4 of the refund policy, can this exception be approved? Quote the lines you rely on. If section 4 does not cover the case, say so.

The observation stays small. The check stays possible. You can read section 4. You were never going to reread forty pages to audit one answer, and the loop knows, in practice, that you will not.
